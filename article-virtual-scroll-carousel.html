Performance Carousel Virtual Scroll

Virtual Scroll for Multiple Media Images in Carousel (Deep Dive)

AS
Avudaiappan S
Senior Frontend Developer
calendar_month February 17, 2026
schedule 10 min read

When we use a carousel with 50–100 images (or image + video mix), the biggest mistake we make is: we render everything. Even though the user sees only one slide. That's wasted DOM, wasted memory, and unnecessary image downloads. Let's actually implement virtual scroll properly.

The Problem: Rendering Everything

Most carousel implementations render all slides into the DOM upfront. With 50–100 media items, that means:

  • Dozens of unused DOM nodes consuming memory
  • Images downloading in the background even if never viewed
  • Re-render costs multiplied across every layout cycle
  • Mobile performance suffering under structural weight

The user sees one slide. Why should the browser pay the cost of a hundred?

Instead of just saying "use virtual scroll", let's actually implement it properly — step by step.

Core Idea

We maintain a currentIndex, a buffer size, and dynamically calculate the visible range. We translate the container instead of re-rendering the full list, and preload next/prev slides safely.

Step 1 – Basic Structure

Assume we have 100 slides and the user is looking at the first one:

setup.js
const slides = ref([...]) // 100 images
const currentIndex = ref(0)
const buffer = 2

Instead of rendering all slides with <div v-for="slide in slides" />, we compute only the required slides.

Step 2 – Calculate Visible Window Properly

Instead of filter (which still loops the full array), use slice. Much more efficient:

visibleWindow.js
const startIndex = computed(() => {
  return Math.max(currentIndex.value - buffer, 0)
})

const endIndex = computed(() => {
  return Math.min(
    currentIndex.value + buffer + 1,
    slides.value.length
  )
})

const visibleSlides = computed(() => {
  return slides.value.slice(
    startIndex.value,
    endIndex.value
  )
})

Now we're not looping the entire 100 items every time. We slice only the needed part.

Step 3 – Offset Positioning (Important)

If we render only a subset, the layout breaks. We need to shift the container properly using transform:

offset.js
const slideWidth = 400 // example

const offset = computed(() => {
  return startIndex.value * slideWidth
})

Then in the template:

CarouselTrack.vue
<div class="carousel-wrapper">
  <div
    class="carousel-track"
    :style="{
      transform: `translateX(-${offset}px)`
    }"
  >
    <div
      v-for="(slide, index) in visibleSlides"
      :key="slide.id"
      class="slide"
      :style="{ width: slideWidth + 'px' }"
    >
      <img
        :src="slide.url"
        loading="lazy"
        decoding="async"
      />
    </div>
  </div>
</div>

Now:

  • Only 3–5 slides exist in the DOM
  • Position stays accurate
  • Animation remains smooth

Step 4 – Handle Swipe / Navigation

When the user clicks next or previous:

navigation.js
function next() {
  if (currentIndex.value < slides.value.length - 1) {
    currentIndex.value++
  }
}

function prev() {
  if (currentIndex.value > 0) {
    currentIndex.value--
  }
}

Because the visible window auto-recalculates, the DOM automatically updates. No manual re-render needed.

Step 5 – Preload Adjacent Images (Smart Optimization)

Sometimes when the user swipes fast, the next image loads late. We can manually preload the next slide:

preload.js
watch(currentIndex, (newIndex) => {
  const nextSlide = slides.value[newIndex + 1]
  if (nextSlide) {
    const img = new Image()
    img.src = nextSlide.url
  }
})

This ensures smooth UX even during fast navigation.

Step 6 – Handling Mixed Media (Image + Video)

If slides contain a mix of images and videos:

slideData.js
{
  type: 'image' | 'video',
  url: '...'
}

Render conditionally:

MixedMediaSlide.vue
<div v-for="slide in visibleSlides" :key="slide.id">
  <img
    v-if="slide.type === 'image'"
    :src="slide.url"
    loading="lazy"
  />

  <video
    v-else
    :src="slide.url"
    preload="metadata"
    controls
  />
</div>

Important:

  • Never preload a full video
  • Use preload="metadata"
  • Otherwise memory explodes

Step 7 – Avoid Layout Shift

Always set explicit dimensions to prevent CLS (Cumulative Layout Shift) issues:

carousel.css
.slide {
  aspect-ratio: 16 / 9;
  flex-shrink: 0;
}

Or explicitly set height. Without this, virtualization won't save you from CLS issues.

Why This Is Better Than Just Lazy Loading

Lazy loading only delays the network request. It does NOT reduce:

  • DOM nodes
  • Memory footprint
  • Re-render cost

Virtualization reduces structural cost. Lazy loading reduces network cost. Both together = a scalable solution.

Real-World Scenario

If we build any of these, virtual scroll becomes mandatory:

  • Product gallery
  • Large portal media section
  • CMS article gallery
  • 100+ image dataset viewer

Especially when multiple carousels exist on the same page. Otherwise mobile performance will suffer.

Advanced Improvement – Responsive + Virtualized

Instead of a fixed slideWidth, use ResizeObserver to detect container width dynamically. Then calculate slideWidth reactively:

responsive.js
const containerRef = ref(null)
const slideWidth = ref(400)

onMounted(() => {
  const observer = new ResizeObserver((entries) => {
    for (const entry of entries) {
      slideWidth.value = entry.contentRect.width
    }
  })
  if (containerRef.value) {
    observer.observe(containerRef.value)
  }
})

That makes your carousel responsive and virtualized — the best of both worlds.

Final Thought

A carousel is not just UI. It's memory management.

If we control what we render, we control performance. That's proper frontend engineering.
